📡 1. Data Sources & LULC Class Mapping

🛰️

CoRE Stack — Primary Data Source

  • Provider: Foundation for Ecological Security (FES), via CoRE Stack REST APIs
  • Satellite: Sentinel-2 multi-temporal imagery, classified using IndiaSAT algorithms
  • Resolution: 10 meters per pixel (~0.01 ha per pixel)
  • Coverage: Active tehsils where CoRE Stack processing pipeline has run
  • Temporal Range: Fiscal years 2017-18 through 2024-25 (varies by tehsil)

2. Boundary Selection & Village Resolution

🏘️

How the Village Boundary Is Obtained

  1. CoRE Stack Registry: User selects State → District → Tehsil → Village. The village polygon (MultiPolygon GeoJSON) is fetched from the CoRE Stack API.
  2. GeoJSON Upload: User first selects State/District/Tehsil (for raster data context), then uploads a custom .geojson polygon boundary.
Why admin context is required for uploads: GeoServer raster URLs follow the pattern LULC_{yy_start}_{yy_end}_{district}_{tehsil}_level_3. Surface water and MWS geometry data is indexed per-tehsil. Without the admin context, the system cannot locate the correct satellite imagery.
⚙️

Spatial Processing — Pixel Extraction Pipeline

Once the village boundary is resolved, satellite data is processed pixel-by-pixel:

GeoTIFF from GeoServer
→
Read windowed bbox
→
Clip to polygon mask
→
Histogram of pixel classes
→
Pixel counts × pixel area (ha)

Pixel Area Computation

pixel_area_ha = (res_deg × m_lat) × (res_deg × m_lon) / 10,000

Where m_lat and m_lon are latitude-dependent meters-per-degree:

m_lat = 111,132.92 − 559.82 × cos(2 × lat_rad)
m_lon = 111,412.84 × cos(lat_rad)

At the centroid latitude of the village. At 10m resolution this yields ~0.01 ha per pixel.

🌱 3. Cropping Intensity — How It Is Derived

🌱

Cropping Intensity Trends

Derivation Steps

  1. Extract pixels inside the village boundary from the LULC Level 3 raster for each fiscal year.
  2. Count crop pixels by class:
    • Class 8 (Single Kharif) + Class 9 (Single Non-Kharif) = Single Crop
    • Class 10 = Double Crop
    • Class 11 = Triple Crop
  3. Convert to hectares: area_ha = pixel_count × pixel_area_ha
  4. Compute the Intensity Index using the GCA/NSA formula below.

GCA / NSA Formula

Gross Cropped Area (GCA) = Single×1 + Double×2 + Triple×3

Net Sown Area (NSA) = Single + Double + Triple

Cropping Intensity Index = GCA / NSA
Interpretation: An index of 1.0 means all land is cropped once per year. An index of 2.0 means an average of 2 harvests per year. Higher values indicate more intensive agricultural practices.

💧 4. Surface Water Bodies — How It Is Derived

💧

Seasonal Surface Water Availability

Derivation Steps

  1. Fetch MWS polygon geometries for the selected tehsil from CoRE Stack API.
  2. Compute village–MWS overlap fractions using polygon intersection:
    fi = Area(Village ∩ MWSi) / Area(MWSi)
  3. Fetch surfaceWaterBodies_annual records indexed by MWS UID. Each record has seasonal water areas:
    • kharif_area_in_ha — Monsoon (Jun–Sep)
    • rabi_area_in_ha — Winter (Oct–Feb)
    • zaid_area_in_ha — Summer (Mar–May)
    • total_area_in_ha — Combined annual
  4. Weighted aggregation to the village level:
    village_kharif_ha = Σ (MWS_i_kharif × overlap_fraction_i)
Note: Surface water data comes from pre-computed vector records, not from raster pixel counting. The same weighted overlap formula is applied to each seasonal field to derive village-level values.

🌳 5. Vegetation & Deforestation — How It Is Derived

🌳

Vegetation & Deforestation Analysis

Tree Cover Trends

For each fiscal year, count LULC pixels classified as Trees/Forest (class 6) within the village:

tree_cover_ha = count(pixels where class == 6) × pixel_area_ha

Deforestation Analysis (First Year vs Last Year)

  1. Align pixel arrays from the first and last available year (same spatial extent).
  2. Deforestation: Pixels where class was 6 (Forest) in Year 1 but NOT 6 in Year N.
  3. Afforestation: Pixels where class was NOT 6 in Year 1 but IS 6 in Year N.
  4. Forest Retention: Pixels remaining class 6 in both years.

Transition Labels

When a pixel transitions FROM forest, the report tracks what it became:

To ClassTransition Label
1Forest → Built Up
2, 3, 4Forest → Water (Kharif/Rabi/Perennial)
7Forest → Barren
8, 9, 10, 11Forest → Farm (consolidated)
12Forest → Scrub Land

Derived Metrics

Degraded Land = Σ (Forest→Barren) + Σ (Forest→Scrub)
Net Change = tree_cover_last_year − tree_cover_first_year

⛰️ 7. Terrain Composition — How It Is Derived

⛰️

Terrain Composition

Derivation

Terrain data is sourced from MWS-level pre-computed records in CoRE Stack. For each MWS overlapping the village:

  1. Compute overlap fraction between the village and each MWS polygon.
  2. Weighted-aggregate each terrain type area:
    village_terrain_type_ha = Σ (MWS_i_terrain_type × overlap_fraction_i)
  3. Sum all terrain types to get total_area_ha.
  4. Compute percentage of each type:
    percentage = (terrain_type_ha / total_area_ha) × 100
